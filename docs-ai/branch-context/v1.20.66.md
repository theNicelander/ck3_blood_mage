# v1.20.66: Blood Knight Creation Expansion & Superior Class Transmutation

## Motivation

- Previously, Blood Mages could only initiate new Blood Mages (`grant_blood_magic_interaction`) while Blood Knights could only initiate new Blood Knights (`make_blood_knight_interaction`). As martial champions of blood magic, Blood Knights should naturally be creatable by both Blood Mages seeking martial protectors and fellow Blood Knights, while occult Blood Mage initiation remains the exclusive domain of Blood Mages.
- Players had no gameplay mechanism to transition between the two mutually exclusive lifestyle traits (`lifestyle_blood_mage` and `lifestyle_blood_knight`). Changing paths required debug commands.
- Under Cast Superior Blood Magic, characters should be able to perform a profound transmutation ritual using 1 Superior Lifeforce to transition between Blood Mage and Blood Knight, carrying over their investment in shared Devotion tracks (`ancient`, `enlightenment`, `benediction`) while resetting class-specific specializations (`bloodline` and `hematurgy` for Mages; `vanguard` and `slaughter` for Knights). This option is restricted to human players.

## Changes

### Key changes

- **Expanded Blood Knight Creation (`make_blood_knight_interaction`):**
  - Updated `is_shown` in `common/character_interactions/bm_blood_knight_interactions.txt` to allow actors with `lifestyle_blood_mage` or `lifestyle_blood_knight` to initiate eligible targets into Blood Knights.
  - Adjusted `on_accept` so Blood Mages initiating a Blood Knight gain `benediction` track XP (+1 for Minor initiation, +1 or +2 for Major initiation), while Blood Knights continue to gain `vanguard` track XP.
  - Retained strict exclusivity on `grant_blood_magic_interaction`, ensuring only Blood Mages can create other Blood Mages.
- **Superior Class Transmutation Effects (`bm_transmute_to_blood_knight_effect`, `bm_transmute_to_blood_mage_effect`):**
  - Implemented in `common/scripted_effects/bm_blood_mage_lifecycle_effects.txt`.
  - Captures current character XP in `ancient`, `enlightenment`, and `benediction` into temporary variables prior to trait removal.
  - Consumes 1 Superior Lifeforce (`remove_character_modifier = lifeforce_modifier_superior`, `blood_magic_used_superior = yes`).
  - Swaps the lifestyle traits, resetting class-specific tracks (`bloodline` and `hematurgy` when becoming Knight; `vanguard` and `slaughter` when becoming Mage).
  - Handles commander rules: adds `ignores_gender_army_rules` when becoming a Knight, and safely strips it when becoming a Mage (unless holding the `shieldmaiden` trait).
  - Re-applies the preserved XP to `ancient`, `enlightenment`, and `benediction` on the new lifestyle trait via helper script values.
  - Applies a 5-year cooldown flag (`bm_swap_class_cooldown`).
- **Cast Superior Blood Magic Decision Integration:**
  - Added widget items `bm_superior_transmute_to_knight` and `bm_superior_transmute_to_mage` to `bm_cast_blood_magic_superior_decision` in `common/decisions/cast_magic/bm_cast_blood_magic.txt`.
  - Set `is_shown = { is_ai = no ... }` and `ai_chance = { value = 0 }` to strictly reserve class transmutation for human players.
  - Enclosed transmutation effects within `send_interface_toast`.
- **Script Values & Localization:**
  - Added `bm_transmute_ancient_xp_value`, `bm_transmute_enlightenment_xp_value`, and `bm_transmute_benediction_xp_value` in `common/script_values/bm_blood_mage_story_values.txt`.
  - Added localization and alias keys in `localization/english/bm_cast_blood_magic_self_l_english.yml`.

- **Blood Magic & Blood Knight Initiation Restructuring:**
  - Introduced dedicated religious initiation decisions for Blóðtrú followers in `common/decisions/become_mage/bm_become_blood_mage_decision.txt`:
    - `bm_blodtru_become_blood_mage_decision`: requires Piety Rank 3, Prestige Rank 2, and 500 Piety (`bm_blodtru_initiation_piety_cost`). Directly bestows `lifestyle_blood_mage` and `lifestyle_blood_power`. Checked quarterly by AI (`ai_check_interval = 3`) with 10% base chance and prevalence modifier scaling.
    - `bm_blodtru_become_blood_knight_decision`: requires Piety Rank 2, Prestige Rank 3, and 500 Piety (`bm_blodtru_initiation_piety_cost`). Directly bestows `lifestyle_blood_knight`, `lifestyle_blood_power`, and ignores army gender rules. Checked quarterly by AI (`ai_check_interval = 3`) with 10% base chance and prevalence modifier scaling.
  - Unified the sacred geyser duel decision (`bm_enhance_blood_ritual_decision`): opened to characters of any faith present in Iceland (`c_vestisland`) or Tsushima (`c_tsushima`) meeting the Piety Rank 2 and 20+ skill attribute / trait prerequisites.
  - Preserved universal access to `ask_for_blood_magic_interaction` and `bm_get_blood_magic_from_prisoner_interaction` worldwide.
  - Added full localization sibling keys in `localization/english/bm_decisions_l_english.yml`.
  - Updated architecture docs in `docs-ai/architecture/blood-mage-religions.md`.

- **Comprehensive AI Interaction Audit, Debug Logging Standardization & Modal Interaction Fixes:**
  - **Eliminated AI No-Op Bug in Exclusive Modal Interactions:** Resolved an engine quirk where CK3 AI evaluated modal option combinations including the empty set `{}` (all options `no`). Because `ai_will_do` lacked option scoring and empty-set vetoes, the AI consistently selected zero options (0 piety cost), firing `on_accept` without executing any of the conditional option payload effects. Fixed across all 6 modal interactions (`grant_blood_magic_interaction`, `make_blood_knight_interaction`, `bm_blood_drain_interaction`, `bm_blood_blessing_interaction`, `bm_manifest_lifeforce_interaction`, `bm_bleed_own_vein_interaction`) by:
    1. Setting `can_invalidate_interaction = yes` on every `send_option`.
    2. Adding explicit positive weights for individual options in `ai_will_do`.
    3. Adding an absolute `factor = 0` veto at the end of `ai_will_do` whenever no option is selected (`modifier = { NOR = { scope:opt_1 = yes ... } factor = 0 }`).
    4. Branching `debug_log` inside each `if / else_if` in `on_accept`, with an explicit `else` branch logging `(NO OPTION)` fallback to catch any stray empty payloads.
  - **Expanded Debug Relationship Hierarchy (`bm_debug_relation_tags`):**
    - Reordered evaluation order so high-priority protected roles cannot be masked by broad categories (e.g. spouse/child/councillor being logged merely as "Dynasty" or "Knight").
