# v1.20.55: Trait Track Reusable Variables Refactor & Parity Tuning

## Summary & Motivation
Refactor all fixed numerical modifier values across `lifestyle_blood_mage` and `lifestyle_blood_knight` trait tracks into reusable `@` script variables defined at the top of their respective trait files. Centralizing these values eliminates duplicate hardcoded numbers across tiers, makes balance adjustments simple and consistent, and aligns Blood Knight common stat references with Blood Mage standards.

## Core Concepts & Changes
- **Reusable Trait Track Script Variables**:
  - `common/traits/bm_blood_mage_trait.txt`: Defined 42 reusable script variables categorized by track comments (`# General stats`, `# bloodline`, `# hematurgy`, `# benediction`, `# enlightenment`, `# ancient`). All tier blocks now reference these `@bm_*` variables.
  - `common/traits/bm_blood_knight_trait.txt`: Defined 32 reusable script variables categorized by track comments (`# General stats`, `# vanguard`, `# slaughter`, `# benediction`, `# enlightenment`, `# ancient`). All tier blocks now reference these `@bm_*` variables.
- **Blood Knight Common Stat Standardization**:
  - Replaced legacy `@bm_mage_common_*` references in Blood Knight's `benediction`, `enlightenment`, and `ancient` tracks with `@bm_common_*` (`health = 0.1`, `life_expectancy = 2`, `years_of_fertility = 1`, `epidemic_resistance = 1`), establishing full stat parity.
- **Decision & Localization Tuning**:
  - Added 1-year cooldown to `bm_empower_bloodline_decision`.
  - Refined trait descriptions in `localization/english/bm_traits_l_english.yml`.
  - Updated architecture docs (`blood-mage-decisions.md`, `blood-mage-dynasty.md`, `blood-mage-magic-tiers.md`, `blood-mage-track-xp.md`) to reflect the decision cooldown.

## Key Decisions
- **Self-Contained File Variables**: Defined variables at the top of both trait files independently so that each trait definition remains modular, self-contained, and easily readable without cross-file script value lookups.
- **Descriptive Suffixes**: Used `_tier_50` / `_tier_100` for capstone scaling and `_low` / `_high` for stepped progression stats (e.g. `dread_baseline`, `prowess`, `phase_duration`).
- **Boolean Flags Preserved**: Kept `no_prowess_loss_from_age = yes` as literal engine booleans rather than variables.
