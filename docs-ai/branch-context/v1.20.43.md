# v1.20.43: Fix Seek Power Event Portraits & Character Identity

## Summary & Motivation

Resolves missing character portraits and vague character naming in the Seek Power wilderness encounters (`events/bm_seek_power_events.txt` and `localization/english/event_localization/bm_seek_power_l_english.yml`):
1. **Event Window Portraits Fix**: Portraits in `seek_power.001`, `.002`, `.003`, `.004`, and `.006` were defined at the bottom of the event script blocks (after all `option = { ... }` blocks). In Paradox Jomini engine, GUI event windows ignore portrait declarations placed after options, rendering empty backgrounds. All portrait blocks are now moved to the top of each event definition immediately after `theme = ...` and before `immediate = { ... }` / `option = { ... }`.
2. **Dual-Character Staging in Encounter**: In `seek_power.003`, the player renders on `left_portrait`, the traveler/minor noble renders in 3D on `right_portrait` (`animation = beg`), and when spawned (50% chance), the sworn escort knight renders in `lower_right_portrait` guarded by `trigger = { exists = scope:escort_knight }`. This eliminates the null scope error (`Failed to find applicable culture set for character with id 4294967295`) when the escort does not spawn.
3. **Explicit Character Names & Prowess**: Updated `bm_seek_power_l_english.yml` to display full character names with clickable tooltips and prowess ratings in event descriptions (`[recipient.GetUIName] ([recipient.GetProwess] [prowess|E])`, `[escort_knight.GetUIName] ([escort_knight.GetProwess] [prowess|E])`) and in button option titles and toasts (`[recipient.GetFirstNameNoTooltip]`, `[escort_knight.GetFirstNameNoTooltip]`).

## Core Concepts & Changes

- **Portrait Placement Standard**:
  - `seek_power.001`: `left_portrait = { character = root animation = idle }` at top.
  - `seek_power.002`: `left_portrait = { character = root animation = idle }` at top.
  - `seek_power.003`: `left_portrait` (root), `right_portrait` (scope:recipient), `lower_right_portrait` (scope:escort_knight with `exists` trigger) at top.
  - `seek_power.004`: `left_portrait = { character = root animation = idle }` at top.
  - `seek_power.006`: `left_portrait` (root with `animation = marshal`), `right_portrait` (scope:duel_opponent with `animation = pain` and `trigger = { exists = scope:duel_opponent }`) at top.
- **Narrative & Option Localization**:
  - `seek_power.003.desc` & `desc_escort`: Explicitly identifies the traveler / minor noble and escort knight with prowess ratings.
  - `seek_power.003.c`, `.recruit_knight`, `.knight`, `.battlefield_duel_escort`, `.battlefield_duel_solo`: Uses `[recipient.GetFirstNameNoTooltip]` and `[escort_knight.GetFirstNameNoTooltip]` for distinct button clarity.
  - `seek_power.toast.join`, `.join_knight`, `.knight_crit_win`, `.knight_win`: Dynamic toast notifications naming the defeated or recruited character.

## Key Decisions

- **`lower_right_portrait` for Escort Knight**: Standard `character_event` windows in CK3 do not have a 3D `center_portrait` widget in `character_event.gui` (which only supports `left_portrait`, `right_portrait`, `lower_left_portrait`, `lower_center_portrait`, and `lower_right_portrait`). Staging the traveler on `right_portrait` and the escort knight on `lower_right_portrait` cleanly groups the bodyguard with their noble on the right side of the screen, while leaving `left_portrait` for the player.
- **Safe Null Scope Guards**: Guarded `lower_right_portrait` with `trigger = { exists = scope:escort_knight }` and `seek_power.006` `right_portrait` with `trigger = { exists = scope:duel_opponent }` to ensure zero runtime culture / scope errors in `error.log`.
