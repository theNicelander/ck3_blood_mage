# v1.20-6

## Summary & Motivation

AI context was split into layers by scope of knowledge, because rules, the old standalone context folder and the architecture docs overlapped. Trait inheritance and religion docs were also refreshed to match PR #94 and CK3 1.20, focused only on this mod's systems.

## Core Concepts & High-Level Changes

- **Four-layer split.** Rules (`.agents/rules/`) hold generic CK3 guidance with no `bm_` identifiers. Skills (`.agents/skills/`) hold repeatable procedures. Architecture docs (`docs-ai/architecture/`) hold mod-only knowledge, indexed by a new `README.md`, with an optional "Mod conventions" section. The old standalone context folder is removed.
- **New rules.** `ck3-localization.md` (always on), `ck3-events.md`, `ck3-traits.md`. `ck3-scripting.md` is now always on. The decisions rule was renamed `ck3-decisions.md`.
- **Seven skills.** `validate-change`, `update-docs`, `document-subsystem`, `add-blood-magic-decision`, `add-faith`, `add-trait-track`, `add-game-rule`.
- **Docs refreshed.** `blood-mage-trait-inheritance.md` is new, and `blood-mage-religions.md` covers heritage conversion, faith-gated initiation, the hidden identity doctrine and reformation repair.

## Key Decisions

- **Skills, because only Antigravity is used** and it loads them on demand.
- **Scripting and localization rules are always on** because they apply to nearly every change.
- **Architecture stays mod-only** so generic guidance lives in one place (rules).
- **The old context folder was deleted** because it was stale vanilla dumps and duplicated the architecture docs.
- **`lifestyle_blood_mage` stays non-genetic** because it relies on CK3's explicit inheritance fields rather than `genetic = yes`, which triggers recessive trait logic.
