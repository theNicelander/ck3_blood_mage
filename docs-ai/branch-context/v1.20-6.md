# v1.20-6

## Summary & Motivation

Cleaned up trait inheritance and religion documentation across the architecture and agent context to eliminate legacy base-game references and align docs with features introduced in PR #94 and CK3 1.20. Refocused documentation exclusively on the Blood Mages mod's actual systems.

## Core Concepts & High-Level Changes

- **Trait Inheritance Documentation**:
  - Created `blood-mage-trait-inheritance.md` conforming to `AGENTS.md` (conceptual, no balance numbers, standard structure) explaining direct lifestyle inheritance, birth on-actions, retention auditing, non-hereditary personal empowerment, and lineage enhancements.
  - Replaced `llm_context/trait-inheritance.txt` with a mod-focused reference, stripping vanilla congenital trait lists, tiered genetic calculation tables, and inbreeding mechanics.
  - Registered `blood-mage-trait-inheritance.md` in `docs-ai/architecture/AGENTS.md` and cross-linked in `blood-mage-traits.md` and `blood-mage-prevalence-and-lifecycle.md`.
- **Religion Subsystem Documentation**:
  - Overhauled `docs-ai/architecture/blood-mage-religions.md` to conform to `AGENTS.md` formatting (un-numbered headings, living document banner) and accurately cover systems introduced in PR #94 and 1.20: heritage conversion routing (`bm_convert_to_blood_cult_by_heritage_effect`), faith-gated initiation rules (`bm_initiation_faith_requirement`), the hidden compatibility doctrine parameter (`blood_magic_cult_faith`), and the reformation repair system (`bm_repair_quintessence_reformation_decision`).
  - Added `llm_context/religion.txt` as a technical reference detailing religion family structure, syncretic faiths, mainline rites, triggers, and compatibility mechanics.

## Key Decisions

- **We decided to maintain both architecture docs and context files (`llm_context/`)** so that both human/agent architecture workflows and LLM reference prompts receive clean, mod-accurate documentation without base-game noise.
- **We decided to emphasize the non-genetic nature of `lifestyle_blood_mage`** because the trait deliberately relies on CK3's explicit inheritance fields rather than `genetic = yes` (which triggers recessive trait logic).
- **We decided to document all PR #94 religion additions (conversion routing, reformation repair, initiation faith gating, and hidden identity doctrine)** to prevent discrepancies where architecture docs lagged behind game script.
