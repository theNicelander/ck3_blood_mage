# v1.20.34: Situation Tab Blood Knights (Dynasty & Court) & Blood Knight Story Integration

## Summary & Motivation
Consolidate the Blood Knight roster in the "Blood Magic" Situation panel (`window_situation_list.gui` / `bm_blood_mage_story`) so that it contains all Blood Knights across both the ruler's court and their living dynasty members, eliminating duplicates. Enable Situation panel access for rulers possessing the `lifestyle_blood_knight` trait with dynamic discipline readout.

## Core Concepts & Changes
- **Unified Blood Knight Roster (`bm_blood_retinue`)**:
  - Retains the story cycle variable `bm_blood_retinue` for save compatibility, but updates its localization label to `"Blood Knights (Dynasty & Court)"` (`BM_BLOOD_RETINUE`).
  - In `bm_refresh_blood_magic_rosters_effect`:
    - First adds all courtiers with `lifestyle_blood_knight`.
    - Next iterates all living dynasty members with `lifestyle_blood_knight`, filtering with `NOT = { is_courtier_of = scope:bm_story_owner_character }` to prevent duplicate entries for courtiers belonging to the dynasty.
- **Blood Knight Situation Panel Access**:
  - `bm_ensure_blood_mage_story_effect`: Extended to trigger for characters possessing `lifestyle_blood_knight` in addition to `lifestyle_blood_mage`.
  - `bm_initialize_blood_mage_stories`: Initializes stories on game start for both Blood Mages and Blood Knights.
  - Scripted GUIs (`bm_prepare_blood_magic_story_gui`, `bm_refresh_blood_magic_rosters_gui`, `bm_story_uses_refreshable_character_lists_gui`, `bm_refresh_story_character_lists_gui`): Now permit both `lifestyle_blood_mage` and `lifestyle_blood_knight`.
  - Story cycle icon (`bm_blood_mage_story.txt`): Shows `blood_mage_3.dds` if the owner possesses `lifestyle_blood_knight`, falling back to `blood_mage.dds`.
- **Dynamic Discipline Grid Custom Localization**:
  - Added `BM_BLOOD_MAGIC_DISCIPLINE_GRID` custom localization:
    - If the viewer possesses `lifestyle_blood_knight`: Displays `BM_BLOOD_KNIGHT_DISCIPLINE_GRID` with tracks `ancient`, `enlightenment`, `vanguard`, `benediction`, and `slaughter`.
    - Fallback: Displays `BM_BLOOD_MAGE_DISCIPLINE_GRID` with tracks `ancient`, `enlightenment`, `bloodline`, `benediction`, and `hematurgy`.
  - Added `@bm_vanguard_discipline_icon!` and `@bm_slaughter_discipline_icon!` texticons to `gui/bm_blood_magic_texticons.gui`.
- **Blood Runes Magic Relocation**:
  - Relocated Inscribe Minor Blood Rune option to Cast Minor Blood Magic (`bm_cast_blood_magic_minor.001`), consuming Minor Lifeforce.
  - Aligned Inscribe Major Blood Rune in Cast Major Blood Magic (`bm_cast_blood_magic_major.001`) to consume Major Lifeforce (`blood_magic_used_major = yes`).
  - Confirmed Inscribe Superior Blood Rune in Cast Superior Blood Magic (`bm_cast_blood_magic_superior.001`).
- **Blood Knight Prevalence Game Rule (`bm_blood_knight_prevalence`)**:
  - Added campaign game rule matching `bm_blood_mage_prevalence` options: `player_only`, `one_in_10000`, `one_in_1000`, `default` (1 in 500), `one_in_100`, `one_in_10`, and `everyone`.
  - Added lifecycle entry effect `bm_become_blood_knight_effect` and retention audit `bm_apply_blood_knight_prevalence_retention_effect`.
  - Added AI willingness multiplier `bm_blood_knight_prevalence_ai_acquisition_modifier` to `make_blood_knight_interaction`.
  - Added birth evaluation `bm_apply_blood_knight_prevalence_at_birth` to `on_birth_child` and startup audit `bm_initialize_blood_knight_prevalence` to `on_game_start_after_lobby`.
  - Added yearly pulse review `bm_review_unmarked_blood_knight_prevalence`.
  - Enabled trait inheritance and spontaneous birth rates on `lifestyle_blood_knight` with mutual exclusivity fallback prioritizing Blood Mage.
- **Runtime & Error Log Fixes (PR #141)**:
  - Guarded `potential` block in `lifestyle_blood_mage` and `lifestyle_blood_knight` with `trigger_if = { limit = { exists = this } ... }` to prevent `Wrong scope for trigger: none, expected character` when evaluated with no active character.
  - Replaced invalid modifier `natural_dread` with `dread_baseline_add` across all 9 tiers of Hematurgy in `bm_blood_mage_trait.txt`.
  - Replaced invalid `ai_targets` recipient types (`rivals`, `enemies`) with valid engine target `scripted_relations` in `bm_curse_blood.txt`.
  - Guarded while loop count in `bm_recount_lifeforce_stacks_effect` with `if = { limit = { exists = var:... } ... }` to eliminate unset variable errors during event option tooltip dry runs.
  - Wrapped `is_knight_of` in `custom_description` and provided missing `NOT_IS_A_KNIGHT_OF_CHARACTER_TRIGGER` engine fallback loc.
